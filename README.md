# ADP FDE 客户项目助手

一个面向腾讯云 ADP/FDE 客户交付工作的 Codex Skill，帮助使用者完成需求对接、方案设计、实施准备、配置审查、Badcase 分析、测试评估、上线准备和验收交付。

它的主要目标是推进真实客户项目，而不是提供泛化的课程教学。对于刚开始承担 FDE 工作、尚未形成稳定交付方法的使用者，它可以充当一名证据优先、边界清晰的项目副驾驶。

> 本项目不是腾讯云官方产品，也不是官方认证课程、题库或教材的替代品。涉及腾讯云 ADP 当前功能、限制和操作方式时，应以腾讯云最新官方资料及客户实际环境为准。

## 能做什么

### 1. 需求发现与范围确认

- 从客户聊天记录、会议纪要和需求材料中提炼业务目标与核心场景；
- 区分已确认事实、推断、建议和待确认事项；
- 识别范围缺口、关键依赖、风险和验收条件；
- 生成客户问题清单、需求确认表和场景清单。

### 2. 方案设计与选型

- 判断场景适合标准问答、知识库/RAG、Workflow、Multi-Agent、工具集成或组合方案；
- 输出推荐方案、选择理由、业务流程、系统边界和必要的备选方案；
- 梳理模型、知识、Prompt、变量、节点、工具及人工接手的职责；
- 对未经核验的平台能力标记 `待平台确认`，避免把假设写成产品事实。

### 3. 实施准备与配置审查

- 设计 Prompt、变量、字段映射和接口契约；
- 规划知识整理、切分、更新和权限控制；
- 检查 Workflow 分支、异常出口、重试、幂等和回退机制；
- 设计 Multi-Agent 的角色职责、交接字段和终止条件；
- 生成实施任务、责任分工、风险清单和上线检查表。

### 4. Badcase 调试与评测

- 从意图/分支、RAG、Prompt、变量、节点、工具、输出/兜底、延迟/成本等层级组织证据；
- 形成 Badcase 记录、根因假设、取证计划和条件性修复草案；
- 设计原例、相邻表达、边界输入、异常出口和历史回归测试；
- 在没有执行轨迹时明确证据缺口，不把调查计划冒充完整诊断。

### 5. 上线与验收交付

- 定义测试门槛、灰度范围、停止条件、监控、回退和人工接手机制；
- 生成客户可读的方案、配置说明、项目计划、测试报告和验收报告；
- 在发布或调用客户系统前保留明确的动作确认边界。

## 适用场景

你可以将以下材料交给这个 Skill：

- 客户的初始诉求或零散聊天记录；
- 会议纪要、需求文档、招标文件或现有方案；
- 知识文档、接口说明、字段表和系统清单；
- ADP 配置说明、流程截图、运行日志或 Badcase；
- 测试结果、上线计划和验收要求。

1. 在仓库页面点击 `Code`；

## 工作原则

- 先判断当前项目阶段，再生成对应交付物；
- 清楚区分 `已确认`、`推断`、`建议` 和 `待确认`；
- 只提出会影响方案、范围、依赖、安全或验收的关键问题；
- 优先采用最小可交付结构，避免无证据地扩大为复杂 Workflow 或 Multi-Agent；
- 对可能变化的产品能力优先核验当前官方资料；
- 没有客户配置或官方证据时，只提供条件性设计，不宣称控件已经存在；
- 没有执行证据时，只能形成初步分诊和取证计划，不能宣称已经完成根因定位。

## 安全边界

- 不要在仓库、Prompt 或测试材料中提交客户密钥、账号、个人信息和未脱敏日志；
- 不向用户未指定并授权的外部服务上传或披露客户材料；
- 发布、删除、修改线上配置、调用客户接口、发送消息或提交数据前，应再次取得明确确认；
- 不代替客户作出合规、安全、法律或采购决定；
- 不承诺未经验证的能力、效果、成本、时间、SLA 或合规结果。
